# がっちゃんこ gacchanko

独立に作ったプログラムをキャンバスへ置き、接続の意図をエッジに書く macOS アプリケーションです。グラフと仕様をローカルのファイルへ保存し、**いつもの ChatGPT / Codex / Claude Code セッション**で接続コードを実装します。

アプリ自身は LLM の API を呼びません。API キー、別のモデル契約、バックグラウンドエージェントは不要です。利用するコーディングエージェント側には、対象のローカルファイルを読み書きできる環境が必要です。

## 起動

開発・共有先は [yamakkaji/gacchanko](https://github.com/yamakkaji/gacchanko) です。ソースからビルドするには macOS と Xcode Command Line Tools が必要です。

初回はリポジトリを取得してビルドします。

```sh
git clone https://github.com/yamakkaji/gacchanko.git
cd gacchanko
./build.sh
open dist/gacchanko.app
```

以後はアプリを終了してから、リポジトリ内で次を実行してください。

```sh
git pull --ff-only
./build.sh
open dist/gacchanko.app
```

ビルドした `dist/gacchanko.app` は単体で起動できます。アプリ本体やビルドキャッシュは Git の管理対象から除外しています。作成する接続プロジェクトはリポジトリの外へ保存すると、アプリのソースと分けて管理できます。

アプリ実行時の外部ライブラリ、Python、Node.js、npm、uv は不要です。

## 最初の使い方

1. Finder からリポジトリやディレクトリを中央のキャンバスへドロップします。「＋ コンポーネントを追加」からフォルダ、URL、空のモジュールも追加できます。
2. ノードの右側にある出力ポートから、別のノードの左側の入力ポートへドラッグします。出力、入力の順にクリックしても接続できます。
3. 線を選び、名前・形式・実現したいことを右側へ記入します。要求と応答は一つの双方向エッジとして表せます。
4. 「保存」で新しい `.gacchanko` プロジェクトフォルダを作ります。保存後の編集は約0.85秒後に自動保存されます。
5. 「エージェントに渡す」、またはエッジの「この接続をエージェントに渡す」を押すと、絶対パス付きの依頼文がクリップボードへコピーされます。
6. この ChatGPT デスクトップの、ローカルファイルを操作できるチャットへ貼り付けます。Codex CLI / Claude Code をプロジェクトフォルダで開き、同じ依頼文を渡しても構いません。
7. エージェントが仕様を読み、`implementations/` にコードを作り、`reports/` に結果を記録すると、GUIへ約2秒ごとに反映されます。


旧版の `.patchwork` フォルダも「開く」から利用できます。

## キャンバスの操作

- **Shift＋クリック**：ノードの追加選択・選択解除。
- **空白をドラッグ**：四角に全体が入ったノードを一括選択。Shift を押すと現在の選択に追加。
- **選択したノードをドラッグ**：まとめて移動。Delete で一括削除、⌘Z で元に戻す。
- **Space＋ドラッグ / 中ボタンドラッグ**：画面を移動。トラックパッドのスクロールでも移動。
- **線を選んで接点をドラッグ**：入力側・出力側を付け替え。1本だけつながった入力ポートは直接ドラッグでも付け替え。
- **ポートの近くで離す**：互換性のあるポートに吸着して接続。空白や不適切なポートで離した付け替えは元に戻ります。
- **Esc**：範囲選択や接続操作をキャンセル。

エッジは出力から入力へ線に沿って色が変わります。要求・応答の接続はラベルの ↔ と出力側の戻り矢印、実装状態はラベル横の色付きの点で表示します。

左下の「設定」で、エッジの表示をプレビューしながら調整できます。

- グラデーション / 模様 / 両方 / 状態色の切り替え。
- out 側・in 側・模様の色。
- 山形・先細りストライプ、模様の大きさと間隔、線の太さ。
- 矢印の表示・非表示、初期設定へのリセット。

表示設定はこのアプリのローカル設定として保持し、再起動後も復元します。プロジェクトのグラフやエージェント用仕様には含めません。線の太さと模様の大きさ・間隔は縮小表示でも保ちます。

## エージェントとの接続実装を試す

[実装試験と再現手順](examples/agent-handoff/README.md)を用意しました。形式の異なる2つのローカルプログラムを、生成された仕様に沿ってラッパーで接続し、実行テストとレポート反映を確認できます。

## ファイルの構成

| ファイル / フォルダ | 役割 |
|---|---|
| `graph.json` | グラフの正本。ノード、参照先、ポート、エッジの意図を格納 |
| `AGENT_BRIEF.md` | 全体の目的、参照先、作業方法をまとめた生成文書 |
| `connections/<edge-id>/SPEC.md` | 接続ごとの仕様と fingerprint |
| `implementations/<edge-id>/` | エージェントが実装を書く場所 |
| `implementations/shared/` | 接続間で共有するコードの保存先 |
| `reports/<edge-id>.json` | エージェントによる実装・検証の報告 |
| `graph.mmd` | 設計を読むための Mermaid 出力 |

エージェントは `AGENT_BRIEF.md` と `graph.json` を読み、元のプログラムのコードと適用される指示を確認します。元リポジトリを変更しなくても接続コードを管理できます。生成された仕様文書を直接編集しても次の保存で更新されるため、設計の変更は GUI または `graph.json` へ行ってください。

## レポートの形式

`reports/<edge-id>.json` に、次の形式で保存します。

```json
{
  "fingerprint": "connections/<edge-id>/SPEC.md に記載された値",
  "status": "implemented",
  "summary": "実装したことと残っていること",
  "files": ["implementations/<edge-id>/adapter.py"],
  "checks": ["実際に実行した確認コマンドと結果"]
}
```

- `implemented` は実装済み、`verified` は関連する確認を実際に実行済み、`blocked` は未解決事項あり、を表します。
- エッジの仕様、接続するノードの説明・参照先・ポート、または全体の目的を変えると fingerprint が変わり、古いレポートは「要更新」として表示されます。位置の移動では変わりません。
- 状態はエージェントが報告した結果です。GUI 自身が検証を行うわけではありません。構文検査だけで実際の統合実行が成功したと報告しないよう、指示書にも明記しています。
- **参照先リポジトリのソース変更は自動監視しません。** コードを更新した場合は、再検証を依頼してください。
- エッジを削除しても、その実装と以前のレポートは残します。有効な接続は常に `graph.json` を基準に判断します。

外部ツールが `graph.json` を更新した場合、未保存の編集がなければ再読み込みします。編集中の場合は通知を表示し、古い状態での上書きを拒否します。必要なら「未保存分を JSON 書き出し」で退避してから再読み込みしてください。

## v0.1 の範囲

- ノードの配置、パン、ズーム、ポート接続、要求・応答エッジ、自然言語での仕様編集。
- ノード・接続の削除、Undo / Redo、保存・再読み込み、指示書の生成、レポートの読み込み。
- ローカルの参照先を追加すると、README の先頭部分を説明欄へ取り込みます。これは静的な抜粋であり、API の推論や自動解析ではありません。
- リポジトリ URL は参照先として保存します。自動 clone は行いません。
- ChatGPT のチャットへ自動送信しません。依頼文を貼り付ける操作で、現在使っているセッションへ作業を渡します。
- プログラム実行、LLM 推論、接続コードの自動生成、ループの実行スケジューラはアプリの機能に含めていません。接続の実装は依頼先のコーディングエージェントが担当します。
- ポート名は手動編集できます。接続中のポートを削除・改名する場合は、先にそのエッジを削除してください。
- 他のマシンへプロジェクトを移す場合、絶対パスの参照先を設定し直してください。

## 開発と検証

```sh
./build.sh
./dist/gacchanko.app/Contents/MacOS/gacchanko --self-test
```

Swift のコアテストでは、保存の往復、仕様書生成、レポート読み込み、仕様変更の検知、外部変更との競合、パス検査、削除時のコード保持など16項目を検証します。

UI の DOM テストには開発用の `jsdom@26.1.0` が必要です。

```sh
npm install --prefix .qa --no-save jsdom@26.1.0
NODE_PATH="$PWD/.qa/node_modules" node tests/dom-test.cjs
NODE_PATH="$PWD/.qa/node_modules" node tests/appearance-test.cjs
```

このテストではネイティブブリッジを模擬して、ポート接続、入力、保存への受け渡し、レポート表示、複数選択、範囲選択、グループ移動・削除、パン、矢印、Undo / Redo などを検証します。表示設定の保存・復元、設定値の検査、折り返し・ループでのグラデーションも検証します。実際の macOS ウィンドウや Finder のドラッグ＆ドロップを検証するものではありません。

GUI を起動できる開発環境では、実際の WebKit とネイティブブリッジを使う追加のテストも用意しています。

```sh
open -n dist/gacchanko.app --args --ui-test "$PWD/tests/native-ui-result.json"
```

ネイティブウィンドウの操作は承認されなかったため、画面のレイアウトと磁石のような接続の付け替えはブラウザプレビューで確認しました。保存処理のコアテスト、DOM テスト、実際の Swift ストアと生成ラッパーを使う受け渡し試験も実施しています。Finder のドロップやネイティブの保存ダイアログの操作は利用環境での確認が残っています。

グラフを外部で変更した後、GUI を使わず指示書を更新するには次を実行できます。

```sh
./dist/gacchanko.app/Contents/MacOS/gacchanko --refresh /absolute/path/to/project.gacchanko
```

フロントエンドは `web/`、macOS シェルは `Sources/main.swift`、保存と指示書生成は `Sources/Project.swift` にあります。

## 将来の Tauri 対応

画面は HTML / CSS / JavaScript、現行のデスクトップ部分は Swift です。現在も `.app` 単体で起動し、Web サーバーを常駐させる構成ではありません。

画面とデスクトップ機能の連携を `web/bridge.js` へ分離しました。画面は共通のホストインターフェースのみを呼び、Swift 固有の API に依存しません。将来はこの通信部分とネイティブ処理を Tauri / Rust へ置き換え、グラフ編集画面と保存形式を継続利用する設計です。Tauri 版自体はまだ実装していません。

コマンド、イベント、移植範囲は [設計文書](docs/architecture.md) に記載しています。
