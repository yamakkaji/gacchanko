# テスト範囲

## 自動確認

```sh
npm run test:store
npm run test:integration
npm run test:ui
```

- Rustの14テスト：保存・検証・保護・提案・履歴・レポート・パス・原型指示・ファイル判定。
- `tests/store-scenarios.cjs`：保存、再起動、レポート状態、保護と解除、コード保持、提案の部分採用と却下、不正JSON、未接続エッジ、原型の版固定など42操作を実行。
- `tests/tauri-compat.cjs`：2種類のサンプルで旧版のfingerprintとの一致とRustでの再オープンを確認。
- UI回帰テスト：接続・付け替え・未接続エッジ・自己ループ、レイヤー、複数／範囲選択、移動、Undo/Redo、外観、Inspector、言語、チュートリアル。

移行前にSwift/Rustで一致を確認した42操作の結果を `tests/fixtures/store-scenarios.json` に保存しています。グラフ、fingerprint、レポート、変更フィールド、変更ファイル、保護違反、履歴件数、操作の成功／拒否を比較します。絶対パス、JSON整形に依存するrevision、コミットID・日時・メッセージ、エラー文言は比較対象外です。基準データの更新は仕様変更のレビューとともに行い、自動で再生成しません。旧版ソースはGit履歴の `19d89be` に残っています。

## 実ウィンドウでの自動テスト

```sh
npm run test:native
```

デバッグビルドの専用ウィンドウで編集操作とRust保存処理を検証します。一時プロジェクトと非永続WebViewを使い、結果JSONの場所をターミナルに出力します。失敗・タイムアウトは非ゼロ終了です。

2026-10-13にmacOS実機で72項目の成功が報告されています。その後、ウィンドウのドロップ通知からノード追加・座標変換までの2項目を追加しました。この追加分は実機での再確認が必要です。合成イベントによるテストは、Finderからの実際のドラッグ操作を保証しません。

手動確認の対象は、ファイル選択での保存／開く、Finderからのドロップ、未保存で閉じる／終了するときの確認です。Windowsの表示倍率とパスも実機で確認してください。

## 旧版からの移行

旧Swift版の `.gacchanko` プロジェクトはそのまま開けます。アプリの外観・言語設定は再設定してください。ノード追加ダイアログはフォルダ選択で、個別ファイルはドロップかパス指定で追加します。「開く」はプロジェクトフォルダを選択します。旧CLIの `--project` / `--refresh` は提供しません。生成先の経路上にあるシンボリックリンクは拒否します。
