## 発見した問題と修正

| 問題 | 影響・条件 | 対応 |
|---|---|---|
| 内部Git履歴の下位パスが未検査 | 細工したプロジェクトの `history.git/objects` などをリンクにすると、履歴保存がプロジェクト外へ書き込む。回帰テストで修正前に再現 | libgit2を呼ぶ前に内部ツリーを検査。リンク・Windows reparse point・特殊ファイル・外部オブジェクト参照を拒否。外部Gitテンプレートの取り込みも無効化 |
| 特殊ファイルの読み込み | `graph.json` やREADMEなどがFIFOの場合、読み込み開始時に停止し得る | 開く前と開いたハンドルで通常ファイルか確認。Unixでは最終パスのリンク追跡を禁止し、非ブロッキングで開く |
| 履歴の合計サイズ・走査深さに上限が不足 | ファイルをまとめて保持する処理が大きなメモリを消費。深いディレクトリで再帰が増える | 1チェックポイント100 MB、走査項目数・深さの上限を追加。仕様書への説明文の繰り返し展開も保存前に見積もって拒否 |
| IDから生成する出力先の衝突 | 大文字小文字を区別しないファイルシステムで `a` と `A` が同じ出力先になる。Windows予約名や `shared` にも衝突 | 大文字小文字だけが異なるID、Windowsデバイス名、エッジID `shared` を拒否 |
| `git2 0.20.4` の安全性に関する既知の問題 | 問題のAPIは今回確認したアプリでは使用していないが、依存側に未定義動作の注意情報が存在 | `git2 0.21.0`へ更新し、変更されたAPIに対応 |
| 配布バイナリへのビルド元のパス混入 | Rustのパニック位置情報に、ビルドした人のホームディレクトリが残る。既存のローカルバイナリで確認 | `npm run build`でRustのソースパスを匿名化。再ビルドしたmacOS実行ファイルから個人ホームパスが消えたことを確認 |
| WebViewとCIの追加防御 | 将来のHTML混入や外部Actionのタグ変更への備え | CSPでフォーム送信を拒否し、新規WebViewを拒否。GitHub Actionsの実装をコミットSHAに固定し、checkoutの認証情報保持を無効化 |

ファイル読み込み・リンク検査は、同じOSユーザー権限を持つ悪意あるプロセスとの完全な競合防止ではありません。`immutable`もOSのアクセス制御ではありません。

## 確認した安全上の境界

- アプリはノードのコマンド文字列や生成コードを自動実行せず、参照先URLを自動取得・cloneしません。ファイルを開いただけでコマンドを起動する処理もありません。
- HTMLとして表示するグラフ・レポートの文字列に攻撃用タグを入れ、DOMにタグやイベントハンドラーが生成されないことをテストしました。
- プロジェクト内の出力パスには相対パス・IDの検査とリンク対策があります。ネイティブファイル選択でユーザーが指定した保存・読み込み先と、現在のプロジェクトがファイル操作の中心です。
- エージェント向け指示書に、取り込んだREADMEや説明を権限の根拠にしないこと、認証情報をグラフ・実装・レポートに保存しないことを追加しました。これはエージェントへの指示であり、エージェントの挙動を技術的に強制する仕組みではありません。
