# 設計の属性、原型とvariant、変更履歴

## JSONを正本にする

`graph.json` の `schemaVersion: 1` に後方互換のフィールドを追加しています。旧グラフはそのまま読み込めます。各ノードとエッジは次のフィールドを持てます。

```json
{
  "policy": "mutable",
  "designInstructions": "原型の観測→判断→操作という役割分担を維持する。判断部分を別モデルに置き換えるvariantとして設計する。",
  "derivedFrom": {
    "templateID": "template_pipeline",
    "version": 1,
    "memberID": "node_policy"
  }
}
```

- `policy` は `mutable` / `immutable` / `template`。省略時は `mutable`。
- `designInstructions` は設計上の制約、原型から引き継ぐこと、variantで意図的に変更すること。JSONとエージェント向け文書に保存されます。ノードではDescriptionを編集でき、追加の設計制約はエージェントが設計変更として提案します。エッジの設計指示は「接続の詳細…」にあります。
- `derivedFrom` はvariantの原型ID、版、原型内の対応要素。派生していない要素では省略します。
- 属性はグラフの定義に適用されます。プログラミング言語の型システムではありません。

## 原型は構成そのもの

`template` はゼロから設計する代わりに再利用する構成の原型です。ノード単体でも、複数ノードとその内部エッジを持つサブグラフでも登録できます。C++のコード生成を実行するものではありません。

1. 原型にしたいノードを選択します。Shiftまたは範囲選択で複数指定できます。
2. インスペクタ下部の「原型に登録」（複数選択では「選択した構成を原型に登録」）を押し、原型名と「引き継ぐ構成・役割・許容する差異」を記入します。
3. 左下の「原型 / variants」からvariantを作成します。
4. ノードと内部エッジが新しいIDで複製されます。接続先は複製したノードに付け替わり、すべての要素に版付きの `derivedFrom` が記録されます。
5. variantの要素は `mutable` です。原型を維持した設計を出発点として編集し、意図的な差異は `designInstructions` に記入します。

外部へのエッジはサブグラフに含めません。エッジのインスペクタからの登録では、その両端ノードと両者の内部エッジを登録します。参照パスはコピーされますが、参照先リポジトリ自体は複製しません。

原型はグラフ直下の `templates` 配列に完全な構成として保存します。

```json
{
  "templates": [
    {
      "id": "template_pipeline",
      "version": 1,
      "name": "Observe → decide → act",
      "instructions": "役割分担と内部接続を維持し、モデルや対象環境の違いをvariantとして表現する。",
      "nodes": [],
      "edges": []
    }
  ]
}
```

上の空配列は省略表記です。実ファイルでは `nodes` に少なくとも1つの完全なノード定義を入れ、`edges` には実在するポート間の接続を入れます。原型内部には `derivedFrom` を入れません。

登録済みの原型の版は書き換え・削除できません。エージェントが原型を改良する場合は、同じIDで版番号を増やした定義を追加します。GUIでは別の原型として登録できます。既存variantが参照する版は自動更新されません。原型への準拠は設計指示であり、variantに構成差異を作ること自体は許可します。

## immutableとtemplateの保護

- ノードの定義、エッジの定義と削除をアプリ内で拒否します。位置の移動と、ノード・エッジそれぞれの外観（`appearance`）の変更は可能です。
- 保護ノードの既存接続の削除・付け替えも拒否します。宣言済みポートに新しい接続を追加して利用することは可能です。
- エッジが保護されると、`implementations/<edge-id>/` のコードの追加・変更・削除も外部変更として検知し、履歴への採用を停止します。実装を新規に作る前にimmutableにした場合も、明示的な解除が必要です。
- 保護ノードは `components/nodes/<node-id>/implementation/` の追加・変更・削除も検知し、履歴への採用を停止します。
- `reports/` とノードの `report.json` は実行の報告なので保護しません。`implementations/shared/` は特定エッジの所有物ではなく、保護対象に含めません。
- ノード・エッジともMutabilityで `mutable` を選び、ネイティブの確認を行います。解除操作は履歴に残します。
- 外部の `graph.json` が自分で `policy` を書き換えても、最後に採用したGit版との比較で拒否します。アプリを再起動しても継続します。
- 不正なJSONや保護違反の設計は採用せず、差分・エラーを通知します。「外部変更を退避して戻す」は候補JSONを `.gacchanko/rejected/` に保存してから設計を戻します。実装コードを勝手に巻き戻しません。

これはアプリの保護機構です。同じOSユーザーの権限で直接ファイルやGit履歴を編集する外部プロセスに対するセキュリティ境界ではありません。参照先の別リポジトリの権限も変更しません。物理的に書込を禁止する場合は、エージェントの実行環境側で読取専用マウントや権限の分離が必要です。

## 自動Git履歴と差分

プロジェクトを作成・初めて開いた際に `.gacchanko/history.git` を初期化します。グラフの自動保存、外部からの設計変更の採用、実装・レポート更新のポーリングで、差分がある場合のみコミットします。アプリを閉じている間の個々の編集は監視しません。再度開いた時点の実装・レポートを記録し、設計変更は提案として採用を待ちます。

記録対象は `graph.json`、生成した指示書・接続仕様・Mermaid、`implementations/`、`reports/`、`components/` です。隠しファイル、`__pycache__`、`node_modules`、`venv` は除外し、シンボリックリンクは拒否します。1ファイル20MB、対象10000ファイル未満です。巨大な重みやデータをこのフォルダに置かず、外部のパスで参照してください。グラフは10MB未満、原型は200版までです。

既存の `.git` や親リポジトリのインデックスは変更しません。ネットワークへpushしません。Gitのhooks、外部diff、textconv、グローバル設定を利用せず、保存だけでコードを実行しない設計です。実行環境に `/usr/bin/git` が必要です。

「変更履歴」で版を選ぶと、そのコミットの親との差分を表示します。

- ノード・エッジの追加は緑、定義・位置・外観の変更は橙でキャンバス上に表示。
- エッジの実装変更は紫の破線で表示。
- 削除済みの要素は履歴の一覧から変更前を確認。
- 名前、意図、属性、原型の指示を含む変更前後のJSONと実装コードのGit diffを表示。
- 外部編集の作者は `external / unknown`。ファイル変更だけではCodexとClaude Codeを識別しません。GUI経由の変更は `gacchanko / user`。

履歴画面の一覧は直近40コミットです。古いコミットもGit内に保持します。任意の過去版への復元ボタンはまだありません。必要ならGitでファイルを取り出して確認し、グラフ更新として採用してください。

```sh
git --git-dir=/absolute/project.gacchanko/.gacchanko/history.git \
    --work-tree=/absolute/project.gacchanko log --oneline
```

参照先リポジトリ内のソースやそのGit HEADはこの履歴には入りません。実装プロセスを追うには生成コードをプロジェクトの `implementations/` に保存します。参照先ソースの変更による再検証はエージェントに依頼してください。

ノードの任意フィールド `appearance` は `{ "color": "#715669", "radius": 24, "corners": "alternating", "surface": "filled", "header": "plain" }` の形式です。`radius` は0〜28、`corners` は `uniform|alternating`、`surface` は `filled|outlined|elevated`、`header` は `striped|plain`。省略時は種類別の標準表示です。外観は実装fingerprintの対象外です。公開した原型のスナップショットは外観も含め追記専用です。

## 設計提案の採用

外部の `graph.json` 変更は、保護違反のないものも未採用の提案として扱います。従来の自動再読み込みは行いません。比較画面のチェックボックスは要素単位です。追加ノードとその接続、削除ノードと既存接続など、依存する変更は一緒に選びます。採用前にスキーマ・依存・immutable・原型の保護とディスク版を再検査し、競合があれば書き込みません。

一部採用時は元の提案全体を `.gacchanko/proposals/` に保管し、選択しなかった変更は採用済み設計へ戻ります。Gitには採用結果をユーザーの操作として記録します。却下時も元ファイルを退避します。ローカルに未保存の編集がある場合、採用を無効にします。

## 共通のコンポーネント項目

ノード・エッジのInspectorは同じ6項目を使います。保存形式は既存データとの互換性のため、ノードの名前・説明・種類に `name` / `description` / `kind`、エッジには `label` / `intent` / `mode` を使います。Accessは両方とも `path`、申告した実装状態は `implementationState` です。エッジの追加フィールドは任意で、省略された旧ファイルも開けます。実装レポートは申告欄とは別の検証記録として表示します。

エッジの `appearance` は全体のエッジ表示設定と同じ形式（style、source、target、patternColour、pattern、width、spacing、size、arrows）です。個別設定は保存・履歴・原型への登録に含めます。保護されたエッジでも外観は編集でき、実装fingerprintには含めません。
